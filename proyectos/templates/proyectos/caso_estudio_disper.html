Caso de estudio: Disper

Desarrollo evolutivo e incremental de una aplicación backend construida en tres etapas (Módulos 6, 7 y 8). DISPER es un sistema API REST enfocado en la gestión y organización de tareas con autenticación de usuarios, autorización basada en roles (RBAC) y persistencia en base de datos relacional. El proyecto evolucionó desde servir vistas estáticas/dinámicas básicas hasta convertirse en una API independiente y desacoplada del frontend.

Desafío principal que implicaba

Diseñar e implementar un backend totalmente independiente y flexible que pudiera adaptarse a distintas interfaces de cliente sin acoplar la lógica de negocio. El reto consistió en estructurar una arquitectura limpia capaz de soportar tanto un enfoque de organización por proyectos en hitos pequeños (para medir el avance progresivo) como un registro diario de micro-tareas para retroalimentar al usuario sin la presión tradicional de métricas rígidas de productividad, garantizando al mismo tiempo un manejo seguro de datos y archivos.

Solución propuesta

Se construyó una API RESTful modular dividida estrictamente en capas (rutas, controladores, middlewares y modelos).

  • Prototipado e Integración Inicial: Se implementaron vistas dinámicas y plantillas con Handlebars (hbs) durante las primeras etapas de desarrollo para realizar pruebas del flujo de datos, antes de desacoplar completamente la API REST hacia respuestas en formato JSON.
  • Se implementó autenticación y autorización mediante tokens JWT y cifrado de contraseñas con bcryptjs.
  • Se utilizó Sequelize (ORM) sobre PostgreSQL para abstraer y estructurar el modelo de datos relacional, migrando de consultas manuales a modelos y relaciones mantenibles.
  • Se centralizaron las validaciones de negocio y la seguridad en middlewares reutilizables (validación de IDs, verificación de roles como esAdmin y filtrado/límite de archivos con multer).

Tecnologías y herramientas utilizadas

Entorno y Framework

Node.js, Express.js (v5).

Persistencia y ORM

PostgreSQL (pg), Sequelize, pg-hstore.

Seguridad y Autenticación

jsonwebtoken (JWT), bcryptjs.

Archivos y Middleware

multer (carga y validación de imágenes).

Vistas/Configuración

Handlebars (hbs), bootstrap 5, dotenv.

Herramientas de Desarrollo

nodemon, Postman / Thunder Client.

Principales aprendizajes alcanzados

  • Comprensión práctica del desacople entre Backend y Frontend, comprendiendo cómo la API expone recursos en formato JSON para ser consumidos de manera agnóstica por cualquier cliente web o móvil.
  • Evolución en el manejo de persistencia: paso de la manipulación de conexiones manuales de base de datos a la abstracción de modelos, asociaciones y transacciones con un ORM (Sequelize).
  • Implementación del ciclo de vida de las peticiones en Express mediante middlewares en cadena para validar, filtrar y securizar solicitudes HTTP antes de llegar a los controladores.

Métricas de impacto logradas

  • Mantenibilidad y Seguridad de Código: Centralización de las validaciones críticas (validarId, esAdmin, filtros de formato uploadFile) en middlewares, evitando la duplicación de código de verificación en cada controlador de la API.
  • Optimización de Recursos y Conexión: Eliminación del antipatrón de apertura y cierre manual de clientes SQL (Client) por cada consulta, sustituyéndolo por la gestión eficiente de conexiones del ORM.
  • Cobertura de Funcionalidades: Implementación del 100% de las operaciones CRUD con códigos de estado HTTP estandarizados y estructuración de respuestas consistentes (ok, mensaje, data).
  • Control de Carga de Archivos: Restricción automatizada en el middleware de carga para bloquear archivos que superen los 2MB de tamaño o extensiones no autorizadas (.jpg, .jpeg, .png, .webp).

Habilidades técnicas aplicadas

  • Diseño de arquitectura RESTful y estructuración modular de proyectos backend (rutas, controladores, middlewares, modelos).
  • Modelado de datos relacionales y consultas mediante ORM (Sequelize / PostgreSQL).
  • Seguridad en aplicaciones web: hash de contraseñas (bcryptjs) y protección de rutas privadas con Tokens de Acceso (JWT).
  • Manejo de peticiones multipart/form-data para subida de archivos al servidor (multer).
  • Pruebas de integración de endpoints e inspección de respuestas de la API con Postman.

Este proyecto refleja de forma transparente la evolución técnica real de una base de código backend. Demuestra mi capacidad para tomar un requerimiento inicial, iterar su arquitectura hacia estándares modernos de desarrollo (API REST desacoplada, ORM y seguridad con JWT), y resolver desafíos concretos de validación, manejo de datos y seguridad sin depender de la lógica del cliente.
